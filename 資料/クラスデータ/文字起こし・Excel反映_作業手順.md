# スキル・パッシブ文字起こし → 統合Excel反映手順

> 2026-08-04 更新。データを統合Excel 2本にまとめたので、書き込み先が変わりました。
> 旧手順(クラス別Excel 30本のE列「日本語(正)」に書く方式)は廃止。

## 目的

ゲーム内のスキル・パッシブ画面を画像から文字起こしし、内容確認後に統合Excelへ反映する。

## 保存場所

- スクリーンショット：`資料/パッシブ(ゲーム画像)/`
- **書き込み先：`資料/クラスデータ/黒い砂漠M_スキル・パッシブ.xlsx`**

| 対象 | シート | 書き込む場所 |
| :---- | :---- | :---- |
| スキル・ラバム・闇精霊の怒り | `スキル_<クラス略称>` | 該当スキルの行 |
| パッシブ①② | `パッシブ一覧` | 横=クラス列 × 縦=パッシブ①②のセル |
| プロフィール | `黒い砂漠M_プロフィール.xlsx` の `プロフィール_<略称>` | B列 |

### スキルシートの列

```
skill_id / 種別 / 表示番号 / 名前(日本語) / 区分 / STACK / CT / HIT /
説明(日本語) / 元の説明(検証用) / 装着可能秘伝 / 秘伝装着可否 / 画像パス / 名前(韓国語) / 名前(英語)
```

書き込むのは主に **説明(日本語)・STACK・CT・HIT・区分** の5つ。
`装着可能秘伝` `秘伝装着可否` `画像パス` は触らない
(装着可能秘伝はゲーム側の仕様、画像パスは自動検出)。

### パッシブ一覧のセル書式

1行目にクラス名、本文の先頭に名称ヘッダーを置く。この形を崩さないこと。

```
[日本語名 / 韓国語名 / 英語名]
本文1行目
・効果1
・効果2
```

## 基本フロー

1. ユーザーがスクリーンショットとクラス略称、対象(パッシブ①/スキル番号)を送る。
   - 例：`GDのパッシブ①` `WRのスキル3`
2. 画像内の文章を文字起こしする。
3. 読み取り結果をチャットに全文提示する。
4. ユーザーが内容を確認する。
   - 問題なし：`OK`
   - 誤りあり：正しい文章または修正箇所を送る
5. OKまたは修正確定後、統合Excelの該当セルへ反映する。
6. 保存後にExcelを再度読み込み、文章・シート・書式が維持されていることを確認する。
7. **JSONを再生成する**(下記)。完了を短く報告する。

## 反映後に必ず実行する

Excelを直しただけではHPに反映されない。生成スクリプトを回す。

```bash
python scripts/parse_master.py && python scripts/parse_descriptions.py
```

その後 `npm test` が通ることを確認する。GitHubのmainへpushすると本番に反映される。

## STACK / CT / HIT の入れ方 (まな指定ルール)

説明本文から数値を切り出して専用列に入れる。HPでは `STACK:〇　CT:〇　HIT×〇` と表示され、
値の無い項目は表示されない。

- **対象は「最大使用回数 → 再使用待機時間 → 最大〇打撃」と並ぶ、その直後の1行だけ。**
  説明の後ろの方に出てくる「最大〇打撃」は列に入れず、本文にそのまま残す
- 単独行(「・最大2打撃」)は数値化して本文から消す
- 条件付き行(「・スキルボタン長押しで最大2打撃」)は **本文に残したまま** HIT列にも数値を入れる
  (条件が情報として必要なため)
- 「最大〇ヒット」も「最大〇打撃」と同じ扱い
- 記載が無ければ空欄にする(HPでは `STACK:1　CT:5` のように出る)

## 文字起こしの注意点

- 精度を最優先する項目：
  - スキル名・効果名
  - 数値、秒数、回数、重複数
  - `%`、`+`、`-`、倍率
  - PVP・HP・MPなどの英字
  - 再使用待機時間
- 画面の色分けは文章の構造判断に利用するが、Excelには通常の文字として入力する。
- 見出し効果の配下は全角スペースを付けて字下げする。
- 箇条書きは `・` を使用する。
- ユーザーが送った修正版を最終正解として扱う。
- 画像と既存Excelの内容が異なる場合は、最新スクリーンショットとユーザー確認済み文章を優先する。
- 画像に既存Excelにはない行がある場合は、必要な行を追加して日本語を欠落なく入れる。

### 用語の統一

| 使わない | 使う |
| :---- | :---- |
| スタン | 気絶 |
| 黒精霊 | 闇精霊 |
| 技術 | スキル |
| ヒット | 打撃 |

名称(固有名詞)は置換しない。例:「タイドスタンプ」はそのまま
(過去に一括置換で「タイド気絶プ」に壊した事故がある)。

## Excel反映時の注意点

- 対象シート・対象セルを必ず確認する。
- **`元の説明(検証用)` 列は移行前の文章の控え。書き換えない**(いずれ削除予定)。
- 既存の色、罫線、列幅、行の書式を維持する。
- 長文はセル内改行(Alt+Enter)を使う。1セルに全行を入れる。
- 保存後に再読み込みし、文字化け・欠落・書式崩れがないか確認する。
- **AIが書き込む場合の注意**: openpyxl で空セルを書くときは `ws.cell(row, col, value=None)`
  ではなく `cell.value = None` を使う。前者は「値を設定しない」扱いになり前の値が残る。

## 進捗管理

反映済みかどうかは統合Excelを直接見れば分かるので、この文書では管理しない。

## 再開時の依頼例

```text
次、XXのパッシブ①
```

スクリーンショットを添付すれば、文字起こしから再開する。
