# 19. 秘伝OCR読み取り登録 引き継ぎ [進行中] (2026-08-05時点)

> このセッションはここまで。**別のPCで続きをやる。** 再開時は下の「再開時の入口」から。

## 背景・目的

スキル秘伝はゲーム内でほぼランダムに集まる。所持秘伝を登録するのに今は
「タイプ→効果→等級」を1個ずつ手動で選ぶしかなく、まなから「めんどうなので、
スクショを送ったら読み取って仮リストを作りたい」という相談があった。

条件が2つある:

- **画像はまなが受け取りたくない** (他の利用者のスクショを預かる責任を負いたくない)
- 今**テザリングでしか画像を送れない** (開発中のやり取りで画像を何度も送るのは避けたい)

→ どちらも「**ブラウザ内で完結させ、画像をどこにも送らない設計**」にすれば同時に解決する。
サーバーを持たないこのサイトの方針(データは全部ブラウザ内)とも一致する。

## 分かったこと (2026-08-05に検証済み)

- 秘伝の選択肢は全部で**31種類**(7タイプ×効果)しかない。「読んだ文字が31択のどれに
  一番近いか」という当てものに帰着できるので、文字認識が完璧である必要はない。
- タイプの見出し(守護/無欠/鮮明/整った/微か/煌めく/系列)を先に読むと、候補が
  最大7個まで絞れる。
- 効果の等級(深淵/太古/混沌)は、読み取れた数値から一意に決まる
  (無欠の`flawless_debuff`だけ2値目まで見る必要がある)。
- 系列タイプは効果名がそのままブランチ名(アール/セルト/アヒブ/ラブリフ)なので、
  見出しだけで確定する。
- まなが実際のゲーム画面のスクショを見せてくれ、レイアウトを確認できた:
  - **詳細ポップアップ**: 秘伝1個ずつ「◆タイプ／効果+数値」の2行で出る。最も読みやすい
  - **秘伝の櫃(インベントリ一覧)**: 「装着中：〇〇／タイプ／効果+数値」の3行が繰り返す。
    装着中のスキル名が付くので、同じ効果が複数写っても別々の所持品として区別できる
  - **スキル装着画面の中央パネル**: 枠タイプ見出し+「アイテムがありません。」で
    空き枠が分かる → **My編成そのものの復元も将来的に狙える**
- 上記をもとに照合ロジック(タイプ見出し検出→効果のあいまい一致→数値から等級判定)を
  実装し、実際のスクショの文言を使ったテストケースで動作確認した
  (Node.jsで直接検証。OCRが「使用→便用」のように誤読した想定のケースでも
  正しく判定できることを確認済み)。

## 作ったもの

**検証用ツール(単一HTML、非公開・使い捨て)**: `資料/検証ツール/秘伝OCR検証ツール.html`

- Tesseract.js をCDNから読み込み、**ブラウザの中だけで**OCR処理する
- 画像はどこにも送信されない。読み取り結果(テキスト)だけがまなの手元に残る
- 31効果のデータは埋め込み済み (2026-08-04時点の `src/game-rules/skill-sigil.json` から書き出し)
- **git未追跡**(あえてコミットしていない。使い捨てで外部CDN依存のため)

使い方: まなが自分のPCでこのファイルを開き、実際の秘伝スクショをドラッグ&ドロップ /
Ctrl+V貼り付け → 読み取り結果がテキストで出る → そのテキストをコピーしてAIに返す、
という運用。**画像そのものはやり取りしない。**

## まだやっていないこと (次のPCでの作業はここから)

Tesseract.js が実際のスクショからどの程度正しく文字を読めるか(OCR自体の精度)は

   何枚か読み込んでもらい、「読み取り結果まとめ」欄のテキストを見せてもらう
2. 判断基準は **「手入力より速いか」**

## 精度が良かった場合にやること

1. 検証ツールの照合ロジック(タイプ見出し検出・あいまい一致・数値からの等級判定)を
   `src/logic/ocrMatch.ts`(想定)として正式に移植する。既存の `equip.ts` 等と同じく
   自己完結させ、既存ロジックは変更しない方針を踏襲する
   (ロジック本体は検証ツールのHTML内 `<script>` に書いてあるので、そこから移せる)
2. `tesseract.js` を `npm install` で正式な依存関係に加える(現状はCDN読み込みの
   検証版のみ)
3. 所持秘伝登録画面(Inventory)に「スクショから読み取る」導線を追加
4. **読み取り結果は必ず確認・編集できる下書き画面を挟んでから登録する**
   (自動確定はしない。1件ずつ効果・等級をプルダウンで直せるようにする)
5. 画像は読み取り後にメモリ上から破棄し、保存・送信は一切しない
6. テストを追加 (`tests/ocrMatch.test.ts` 想定)

## 精度が悪かった場合の代替案

- 詳細ポップアップ(1件ずつの拡大画面)だけに絞って再検証する。一覧画面より
  文字が大きく安定するはず
- それでも厳しければ、スクショをまな自身が見て仮リストを作り、既存のバックアップ
  復元機能(Excel)で取り込む運用に留める(コード化はしない)
